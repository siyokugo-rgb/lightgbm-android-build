# NAR Point-in-Time Data Contract

## Purpose

競馬予測時点で未来情報を特徴量へ混入させないため、
NARデータの利用可能時点とDomain Model境界を定義する。

## Domain boundary

- HorseEntry = 発走前情報
- HorseOutcome = 実際に競走した馬の結果
- HorseNonStart = 出走取消・競走除外などの非出走確定状態
- Payout = 発走後情報

HorseEntry に着順・タイム・払戻などの発走後情報を入れない。

HorseOutcome / Payout を予測特徴量生成へ渡さない。

HorseNonStart は取得可能時刻を確認せず
予測特徴量生成へ渡さない。

## PIT categories

### PRE_RACE_STABLE

比較的早い段階から利用可能な発走前情報。

例:
- 競馬場
- 競走年月日
- レース番号
- 芝ダート区分
- 回り
- 距離
- 条件
- 馬番
- 馬名
- 性
- 齢
- 血統
- 調教師

### PRE_RACE_LATE

発走前情報だが取得可能時刻に注意が必要。

- 発走時刻
- 騎手
- 負担重量
- 馬体重
- 馬体重増減
- 天候
- 馬場状態
- 頭数
- 人気

これらを前日・当日朝・発走直前で一律に利用しない。

### POST_RACE

当該レース予測では使用禁止。

racelist:
- 上がり4F
- 上がり3F
- ハロンタイム
- コーナー通過順

horselist:
- 着順
- タイム
- 着差
- 上がり3F

payback.csv:
- 全払戻情報

payback.csv 自体を予測入力経路から参照させない。

## Special race result audit

1998年8月 horselist.csv では、
着順空欄146件の全件について「着差」欄に
以下の特殊状態が記録されていた。

- 出走取消: 50件
- 競走除外: 44件
- 競走中止: 46件
- 失格: 6件

同月内で次走まで追跡可能なケースを監査した結果、
「全成績」は以下の更新規則と整合した。

- 出走取消: 加算なし
- 競走除外: 加算なし
- 競走中止: 4着以下相当へ1件加算
- 失格: 4着以下相当へ1件加算

同じ馬・騎手の次回騎乗まで追跡可能なケースでも、
「騎手成績」は同じ規則と整合した。

Domainでは、
競走中止と失格は HorseOutcome として区別して保持する。

出走取消と競走除外は HorseOutcome とは分離し、
HorseNonStart として保持する。

発走前で結果未確定の状態は、
HorseOutcome も HorseNonStart も生成しない。

HorseNonStart は最終的な非出走状態を表す。
予測時点で利用可能かどうかは、
取消・除外が確定・取得できる時刻を別途確認して判断する。

未知の特殊結果表記や不正な着順形式は、
既知状態へ推測変換せずFAILさせる。

この監査結果は1998年8月データに基づく。

## NAR provided track records

horselist.csv の「当競馬場成績」は、
1998年8月データでは当該レース発走前までの
当該競馬場における
1着-2着-3着-その他の累積成績と整合した。

ただし盛岡では、
芝競走とそれ以外の競走で成績系列が分離されていた。

最初に馬・生年月日・競馬場だけで
月内連続出走を比較した結果は、
6745件中6692件一致、不一致53件だった。

不一致53件はすべて盛岡であり、
内訳は以下だった。

- 非芝系列から芝系列への遷移: 22件
- 芝系列から非芝系列への遷移: 31件

芝と非芝を別系列として
馬・生年月日・競馬場・系列単位で再検証した結果、
6697件中6697件すべてで期待される更新と一致した。

芝と非芝の両方を走った馬・競馬場の組は48組あり、
芝・非芝の隣接遷移は56件だった。

この56件のうち3件は、
系列が切り替わっているにもかかわらず
別系列の成績値が単純更新期待値と偶然一致したため、
最初の監査では不一致として表面化しなかった。

また、
反対系列の競走を間に挟んだ同系列比較が8件あり、
8件すべてで元の系列が独立して継続していた。

この比較数は、

6745 - 56 + 8 = 6697

となり、再監査件数と整合する。

したがって1998年8月データでは、
「当競馬場成績」は少なくとも
当該競馬場内で芝系列と非芝系列を分離した
発走前累積成績として整合した。

出走取消・競走除外は加算せず、
競走中止・失格は4着以下相当へ1件加算する規則とも
整合した。

ただし、
1998年8月の racelist.csv では
芝ダート区分が大半の競走で空欄であるため、
非芝系列を一般仕様として常にダートと解釈することまでは
確定しない。

この監査結果は1998年8月データに基づく。
現行予測時点での取得可能時刻は別途監査する。

1998年8月の監査では、
芝と明示された競走を芝系列、

実走タイムは horselist.csv では、

「最高タイム良馬場」についても、

## NAR live daily snapshot audit 2026-08-25

2026年8月25日のNAR daily downloadを
JSTの複数時刻で実取得し、
当日CSVが時間経過とともにどのように更新されるかを監査した。

監査証跡は
audit/nar-live-20260825 ブランチに保存した。

最初の保存時刻である09:58:36 JSTでは、
horselist.csv の以下の履歴系情報は既に取得可能だった。

- 騎手成績
- 全成績
- ダート左成績
- ダート右成績
- 当競馬場成績
- うち当距離成績
- 最高タイム
- 最高タイム良馬場

最高タイム系については、
履歴が存在しない馬などでは空欄となるが、
列自体は当日発走前CSVに存在していた。

09:58から13:00までの複数スナップショット比較では、
上記履歴系8列は観測対象馬について変更0件だった。

一方、
人気、馬体重、馬体重増減、天候、馬場、
出走取消、競走除外などは当日中に更新された。

したがってこれらの動的情報については、
過去の最終CSVに保存された値を
任意の予測時刻で利用可能だった値と仮定してはならない。

人気は発走前に繰り返し変化し、
予定発走時刻を過ぎた後にも変化するケースが確認された。

馬体重は朝時点では未入力で、
各レースの発走前に順次入力された。

馬体重列では、
空欄は未配信状態、
数値は計量値取得済み、
「－」は取消等により数値が存在しない状態として
区別する必要がある。

出走取消・競走除外では馬の行自体は削除されず、
着差列に
「出走取消」
または
「競走除外」
が設定され、
人気は空欄となるケースを確認した。

結果反映も一括ではなく段階的だった。

笠松3Rでは予定発走12:45に対して、

- 12:44:17: 結果なし
- 12:45:22: 発走前スナップショットと完全同一
- 12:49:12: 結果なし、競走除外のみ反映
- 12:55:03: 1着・2着・3着と払戻のみ反映
- 13:00:09: 通常出走馬の全着順・タイム・着差が反映

という状態遷移を確認した。

したがって、

payback.csv に対象レースが存在すること、
1着馬が入力済みであること、
または上位3着が入力済みであることだけでは、
レース結果全体が完成したとは判定しない。

少なくとも内部状態として、

RESULT_NOT_AVAILABLE
PARTIAL_RESULT
CORE_RESULT_COMPLETE

を結果取り込み状態として区別できる設計とする。

CORE_RESULT_COMPLETE は、
通常出走馬の着順・タイム・着差など
主要結果が揃った状態を示す。
上がり3F等の後続項目まで
全て反映済みであることは意味しない。

また、
競走除外・出走取消では
結果反映後にタイム列が「0」になるケースがあるため、
タイムを数値として解釈する前に
非出走状態を先に判定する。

「0」を通常の走破タイムとして
最高タイム計算や学習特徴量へ使用してはならない。

予定発走時刻を過ぎても
daily CSVが発走前状態のまま維持されるケースが確認されたため、
予定発走時刻だけを
結果情報の利用可否境界として使用しない。

この監査は2026年8月25日の1開催日に基づく。
履歴系情報が09:58:36 JSTより前の
どの時刻から取得可能かは別途監査する。

## Future JRA support

NARをDomain Modelそのものとは扱わない。

将来的にJRAを追加する場合も、
共通Domainへ正規化して利用する。

地方所属馬の中央遠征履歴が存在するため、
NAR履歴だけを完全な競走履歴とは仮定しない。
